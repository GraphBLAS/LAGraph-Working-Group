## Agenda and Minutes

**Agenda** by Tim Davis

To discuss:  replacing C pointers to array with `GrB_Vectors`, and replacing C
input/output scalars with `GrB_Scalars`.  This will cause additional breaking
changes in the src/ methods, if we make this change.  For example,
`LAGr_Betweenness` takes as input `uint64_t *sources` and `int32_t ns`.  This
could be replaced by a single `GrB_Vector sources`, as is already done in
`LAGr_EdgeBetweennessCentrality`.  (So should `LAGr_Betweenness` be renamed to
`LAGr_VertexBetweennessCentrality`?)

Adding this `GrB_Vector` would also require a descriptor or flag to state which
list of indices should be used for a vector v:  the indices I or values X from
an implicit `GrB_extracTuples (I, X, v)` on the vector.

**Minutes** by Tim Davis

We discussed the LAGraph API, using this spreadsheet:
https://docs.google.com/spreadsheets/d/1-WnAsmrHRYh5KQeJZzMtZYZKiKblGKYOOIkw0MdokuU/edit?usp=sharing

We continued to discuss the input GrB-Vectors for passing in lists of source
nodes and whether or not we needed a descriptor to specify "by value" or "by
index".  Decision: LAGraph will use "by value".  That is, as if:

        if given a GrB_Vector V as input to an LAGraph method:
        GrB_extractTuples (I, X, &nvals, V)
        use (X,nvals) as the input to the LAGraph method

        by index would instead be:
        use (I,nvals) as the input to the LAGraph method

Note that calling `GxB_Vector_extractTuples_Vector` first can be used to do "by
index", if done in user application before calling LAGraph.  Make a helper
function to wrap it.

This only affects the following methods, which can also be renamed as:

    LAGr_Betweenness                -> LAGr_BetweennessCentrality
    LaGr_MultiSourceBFS             -> ..MultiSourceBreadthFirstSearch
    LAGr_RegularPathQuery           -> ??
    LAGr_EdgeBetweennesdCentrality  -> ??

An outlier:

    LAGr_HarmonicCentrality:        uses both indices AND values of
                                    "node_weights" input

Future methods could include a flag to indicate "by value" or "by index", if
they really need it.

For a future meeting:

    Continue discussing using an LAGraph descriptor to pass in details of which
    hardware to use.  However, this could be handled with the GraphBLAS
    `GxB_Context` object.
